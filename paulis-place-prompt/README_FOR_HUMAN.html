YAPPYVERSE Build — Read Me First

This is the ADHD-friendly index. No wall of text. Do these in order.

What you have

Ten HTML spec files. Each one covers exactly one subsystem. A worker (Claude, GLM 5.2, Codex, whoever) opens exactly ONE file and builds exactly ONE thing. Nothing else.

Do this first

1. Open 00_MASTER_INDEX.html. Read section 4 (the routing table) and section 6 (the subsystem list). That's it — you now understand the whole plan.

Do this second

2. Run the Zernio auth flow yourself. It's a browser click. See subsystems/05_zernio_social_posting.html section 3. You get a key, we put it in .env. Total time: 5 minutes.

Do this third

3. Decide on Hermes' runtime. Section 3 of the index gives the three options. Pick ONE. If you have a VPS that stays on (31.220.58.212 already runs Open Brain), use that.

Do this fourth

4. Hand each subsystem to a worker with this exact instruction: "Read subsystems/<N>_<name>.html and produce the code for this subsystem only. Do not read any other subsystem file. Output must satisfy section 10 (acceptance criteria) of that file." Start with subsystem 01 (Hermes). It unlocks everything else.

The five things this build does when it's done

  1. Makes money. Six revenue channels run on cron, autonomously.
  2. Posts to socials. Every revenue event auto-posts to the right platforms via Zernio.
  3. Debates decisions. Every meaningful call goes through an adversarial three-turn Council.
  4. Shows the work. Public visitors walk into a 3D lounge, see the avatars actually working, talk to them like Jarvis.
  5. Gets smarter every night. A nightly loop reads the day's ops and opens PRs to improve the weak axes.

The three laws you enforce as the human

  1. Nothing gets published (Etsy, Creem, KDP, Zernio) without your approval on the specific artifact.
  2. No PR gets merged automatically. Ever.
  3. Daily AI spend cap is $5. If it hits the cap, everything stops until tomorrow.

What to do if a worker gets stuck

Tell them to halt and ask, not guess. The specs are silent on many small things on purpose — those are places where a fresh human decision is worth more than a guess.

Share this whole folder with the team

The plan/ folder is model-agnostic and self-contained. Any worker can pick a subsystem and build it. When you download the ZIP, the ten spec files plus this README are all a new team member needs to onboard.
