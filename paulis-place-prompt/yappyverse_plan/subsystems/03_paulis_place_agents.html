03 — PAULIS-PLACE AGENTS AND ENVELOPES

Repo: PAULIS-PLACE. Files: adws/, adws/adw_modules/paulis_types.py (envelope schemas already drafted), adws/adw_sssf_config/sssf.config.yaml.

1. Purpose

Five agent roles, each with a single well-scoped job, each with a locked envelope schema, each mapped to a character in the 3D world. SSSF discipline: agent proposes, code disposes.

3. The envelope contract (icm/context/ENVELOPES.md)

ScanOutput:
  scan_id:      string
  niche:        string
  signals:      [ { keyword, source, strength_0_100, evidence_url } ]
  cost_usd:     float

ScoreOutput:
  scan_id:      string
  scored:       [ { keyword, opportunity_score_0_100, confidence_0_1, reasoning } ]
  top_pick:     string
  cost_usd:     float

DesignOutput:
  brief_id:     string
  platform:     string
  artifact_kind: enum ("listing" | "post_draft" | "chapter" | "landing_copy")
  fields:       object            # platform-shaped, validated by Publisher
  design_prompt: string or null   # Replicate/DALL-E prompt if image needed
  cost_usd:     float

PublishOutput:
  brief_id:     string
  validated:    boolean
  violations:   [ string ]
  ready_at:     ISO 8601
  cost_usd:     float

4. The SSSF gate contract

Every agent call ends with a code-side gate. Gates are cheap deterministic Python functions in adws/adw_modules/gates.py. They validate the envelope shape (Pydantic), enforce constraints (title length, tag count, cost cap), and either accept or emit a correction. Corrections re-prompt the same session, never restart.

5. Character binding for the 3D world

Each agent role emits a lounge.character_active event when running, so subsystem 07 can animate the mapped character.

6. Acceptance criteria

  1. All 5 roles have entries in sssf.config.yaml.
  2. Envelope schemas exist in Pydantic form and match section 3.
  3. Gates enforce every constraint declared in the schemas.
  4. Each role emits lounge.character_active at start and lounge.character_idle at end.
