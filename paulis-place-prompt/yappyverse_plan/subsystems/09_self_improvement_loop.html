09 — SELF-IMPROVEMENT LOOP

Repo: pauli-hermes-agent, module src/improve/nightly.ts
Reader model: GLM 5.2 (text-only)

1. Purpose

Every night at 03:00 UTC, Hermes reads yesterday's ops reports and pattern candidates, scores the day against the Meadows 12-axis framework, and produces a small number of proposed changes as GitHub PRs. Each PR touches at most one subsystem. Humans review and merge. This is the compound-learning loop — without it, the system does not get smarter.

2. The nightly steps

  1. Aggregate. Read all files in icm/memory/ops/<yesterday>/. Compute per-agent stats: run count, correction rate, cost total, gate violation rate.
  2. Score. For each Meadows axis (Feedback Completeness, Blast Radius Control, etc.) compute yesterday's score.
  3. Compare. Diff against 7-day rolling average. Any axis that dropped by more than 0.5 is a candidate for a fix.
  4. Propose. Dispatch to a plan profile worker: given the axis that dropped and the ops reports for context, propose one specific change. Output is a PR-shaped envelope with target repo, target files, rationale, and expected axis lift.
  5. Judge. Judge on a different model — is the change worth its cost? Does it address the axis? Blast radius ≤ 3?
  6. Promote patterns. Any decision that appeared 3+ times in the last 30 days without contradiction gets promoted to icm/memory/patterns/<slug>.md. Every subsequent agent read this before its own run.
  7. Open the PR. Via GitHub API. Assign to a human reviewer. Never merge automatically.

3. Guardrails

  1. No more than 3 PRs opened per night. If more candidates exist, keep them for later nights.
  2. PRs that touch icm/instructions/ require two human reviewers.
  3. PRs that touch payment code (subsystem 06) or Hermes core (subsystem 01) require three reviewers.
  4. Any PR that would regress a Meadows axis by more than 0.3 is voided by the judge.

4. Acceptance criteria

  1. Nightly cron exists and produces the aggregate + score files.
  2. Meadows score is computed on 12 axes with declared weights.
  3. The PR-open path uses GitHub API with human assignment.
  4. Pattern promotion has a unit test with 3 identical decisions producing a pattern file.
