10 — ICM FOLDER LAYOUT

Applies to: every repo in scope (PAULIS-PLACE, YAPPYVERSE-FACTORY, lovable-ai-dreamweaver, pauli-hermes-agent)
Reader model: GLM 5.2 (text-only)

1. Purpose

Every repo uses the same three top-level folders — icm/instructions, icm/context, icm/memory — so any model, any agent, any human on the team can find the same kind of file at the same relative path in any of the four repos. This is what makes the system portable across models: instructions and context are markdown, memory is JSON, no vision required, no model-specific tool syntax.

2. The three folders — one job each

FolderContainsWritten byRead by
icm/instructions/WHAT to do — role prompts, system laws, escalation rulesHumans (spec authors). Never written by an agent at runtime.Every agent, every run
icm/context/WHERE things live — repo maps, envelope schemas, event bus contract, character registryHumans, plus the self-improvement loop (subsystem 09) when patterns are promotedEvery agent that needs to touch a boundary — API, DB, event, envelope

4. Rules the layout enforces

  1. Instructions never reference specific models. They reference task profiles from context/TASK_PROFILES.md. Swap models at the gateway, not in prompts.
  2. Context files are the only place API contracts live. An agent that touches Zernio reads context/ZERNIO_PERSONAS.md. An agent that touches the event bus reads context/EVENT_BUS.md. No agent guesses.
  3. Memory is write-once per file. An agent that wants to update a report writes a new file with a new timestamp — never overwrites.
  4. The ops/ tree is rotated after 30 days. Older reports either promoted to patterns/ (self-improvement decides) or deleted.
  5. The patterns/ tree is the compound-learning surface. When the self-improvement loop finds a recurring win (or loss), it promotes it here. Every agent reads patterns/ before its own task.

5. Portability check — the model-swap test

The whole layout passes if you can take any prompt file from icm/instructions/, hand it to a fresh model with no other context, and get a valid envelope back. If a prompt cannot survive that test, it is not portable — it has a model-specific assumption baked in and must be rewritten.

6. Acceptance criteria

  1. All four repos have the same top-level icm/ folder shape.
  2. Every file in the tree in section 3 exists (empty files are acceptable — mere presence proves the discipline).
  3. A lint (part of CI) checks that no prompt in instructions/ references a specific model name.
  4. A test hands a random prompt to a stand-in model and validates the returned envelope shape.
  5. The 30-day rotation of ops/ is a nightly job.
